## 1. 학습 후 자동 실행되는 두 단계

각 학습 run은 350 epoch 학습이 끝난 뒤 자동으로 아래 두 단계를 이어서 실행하도록 queue script에 넣어 두었다.

```text
train.py
-> extract_cache.py
-> eval_posthoc.py
```

즉 학습이 끝나면 사람이 바로 평가 명령을 다시 칠 필요는 없다. 다만 완료 여부와 산출물 존재 여부는 확인해야 한다.

## 2. `extract_cache.py`가 하는 일

`extract_cache.py`는 학습된 checkpoint를 다시 로드해서, ID/OOD 데이터 전체를 한 번 forward pass 하며 logits와 penultimate feature를 저장한다.

실행 형태:

```bash
python code/extract_cache.py \
  --config <config.yaml> \
  --run-dir <run_dir> \
  --checkpoint-tag epoch_0350
```

입력:

- config YAML
- run directory
- checkpoint tag: 이번 실험은 `epoch_0350`

읽는 checkpoint:

```text
<run_dir>/checkpoints/checkpoint_epoch_0350.pt
```

저장 위치:

```text
<run_dir>/cache/epoch_0350/
```

주요 산출물:

```text
id_train.pt
id_val.pt
id_test.pt
ood_test_cifar100.pt
ood_test_tiny_imagenet.pt
ood_test_svhn.pt
ood_test_mnist.pt
classifier.pt
cache_metadata.json
```

각 `.pt` 파일에는 보통 다음이 들어 있다.

```text
logits
features
labels
indices, if available
```

이 단계의 의미:

- 모든 detector가 같은 feature/logit cache를 쓰게 만든다.
- OOD detector를 계산할 때 모델 forward를 반복하지 않아도 된다.
- `Mahalanobis`, `kNN`, `GMM`, geometry metric이 모두 같은 penultimate feature 기준으로 계산된다.

## 3. `eval_posthoc.py`가 하는 일

`eval_posthoc.py`는 `extract_cache.py`가 만든 cache를 읽어서 classification, calibration, OOD, geometry metric을 계산한다.

실행 형태:

```bash
python code/eval_posthoc.py \
  --config <config.yaml> \
  --run-dir <run_dir> \
  --checkpoint-tag epoch_0350 \
  --eval-dir eval/epoch_0350
```

입력:

```text
<run_dir>/cache/epoch_0350/*.pt
```

저장 위치:

```text
<run_dir>/eval/epoch_0350/
```

생성되는 JSON:

```text
metrics_classification.json
metrics_calibration.json
metrics_ood_logit.json
metrics_ood_feature.json
metrics_ood_nc_hybrid.json
metrics_geometry.json
detector_params.json
feature_stats.json
```

계산하는 주요 항목:

| 파일 | 내용 |
|---|---|
| `metrics_classification.json` | ID test accuracy, NLL |
| `metrics_calibration.json` | ECE 15-bin, temperature-scaled ECE, fitted temperature |
| `metrics_ood_logit.json` | MSP, MaxLogit, Energy, NegEntropy OOD AUROC/AUPR/FPR95 |
| `metrics_ood_feature.json` | Mahalanobis, Mahalanobis-L2, kNN, kNN-L2, DDU-style GMM |
| `metrics_ood_nc_hybrid.json` | NCC distance, prototype cosine, ViM diagnostic 등 |
| `metrics_geometry.json` | NC1, InterDist, NC3 alignment, covariance spectrum, effective rank 등 |
| `detector_params.json` | score direction, fitting split, GMM/shrinkage 설정 |
| `feature_stats.json` | split별 feature norm 통계 등 |

중요한 convention:

```text
higher score = more ID-like
ID label = 1
OOD label = 0
```

DDU 관련 표기는 포스터에서 항상 다음처럼 쓴다.

```text
DDU-style GMM feature density
```

원래 DDU 전체 reproduction이라고 쓰지 않는다.

## 5. 3-seed aggregation이 하는 일

Aggregation은 seed0, seed1, seed2 결과를 하나의 표로 합치는 단계다.

이번 실험에서 seed0은 이미 있는 zip에서 온다.

```text
/home/ghjin/2027ICLR/2027ICLR/results/WRN_seed0_350eps_girdsearch_0531.zip
```

seed1/seed2는 이번 새 run directory에서 온다.

```text
/home/ghjin/iclr2027_runs/20260611_1142_curie_..._selected_poster/
```

Aggregation의 목적:

1. run마다 흩어진 JSON을 하나의 scalar CSV로 펴기
2. near-OOD와 far-OOD 평균을 계산하기
3. config별 seed0/1/2 평균과 표준편차를 계산하기
4. paired delta table을 만들기
5. 포스터 표와 그림에 넣을 작은 CSV를 만들기

## 8. mean/std table이 하는 일

3-seed mean/std table은 같은 config의 seed0/1/2 row를 묶어서 평균과 표준편차를 계산한 것이다.

예:

```text
config_label = adamw_lr5e-3_wd1e-4
id_test_acc_mean = mean(seed0, seed1, seed2)
id_test_acc_std  = std(seed0, seed1, seed2)
```

포스터 표에서는 보통 다음처럼 표기한다.

```text
94.7 +/- 0.3
0.923 +/- 0.018
```

주의:

- 표준편차는 sample std, 즉 `ddof=1`을 기본으로 쓴다.
- seed가 3개 모두 없으면 main table에 넣지 않는다.
- seed0-only 결과는 `preliminary` 또는 supplementary로 분리한다.

## 9. Paired delta table이 하는 일

Paired delta는 같은 seed끼리 두 config의 차이를 계산한다.

예:

```text
Delta_s = Metric(adamw_lr5e-3_wd1e-4, seed=s) - Metric(sgd_lr1e-1_wd5e-4_anchor, seed=s)
```

그 다음 `Delta_0`, `Delta_1`, `Delta_2`의 평균과 표준편차를 보고한다.

포스터에 넣을 주요 paired comparison:

| Comparison | 의미 |
|---|---|
| `adamw_lr5e-3_wd1e-4 - sgd_lr1e-1_wd5e-4_anchor` | AdamW validation-best vs SGD anchor |
| `adamw_lr5e-3_wd5e-4_anchor - sgd_lr1e-1_wd5e-4_anchor` | AdamW anchor vs SGD anchor |
| `mahalanobis_l2 - mahalanobis` within same checkpoint | L2 normalization recovery |
| `knn_l2 - knn` within same checkpoint | L2 normalization recovery |

Adam `wd=0 - wd=1e-4` comparison은 이번 main paired delta table에서 제외한다. seed0-only supplementary로만 해석한다.
